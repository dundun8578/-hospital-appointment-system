# JMeter压测脚本使用说明

## 📋 压测场景

**场景**：500并发用户同时抢号预约

**流程**：
1. 用户登录（1个线程）
2. 查询排班详情（500并发）
3. 创建预约（500并发）⭐核心
4. 查看我的预约（500并发）

## 🚀 压测步骤

### 1. 环境准备

```bash
# 启动MySQL
# 启动Redis
# 启动RabbitMQ
# 启动医院预约挂号系统（4个模块）
```

### 2. 准备测试数据

```sql
-- 清空之前的预约记录（防止唯一索引冲突）
DELETE FROM appointment WHERE user_id = 1;

-- 确保有可预约的排班
UPDATE schedule SET available_count = 100 WHERE schedule_id = 1;
```

### 3. 运行JMeter压测

```bash
# 非GUI模式压测（推荐）
jmeter -n -t jmeter/scripts/appointment_test_plan.jmx -l jmeter/reports/result.jtl -e -o jmeter/reports/html

# GUI模式（仅用于调试）
jmeter -t jmeter/scripts/appointment_test_plan.jmx
```

### 4. 查看压测报告

压测完成后，打开 `jmeter/reports/html/index.html` 查看详细报告。

## 🔍 性能瓶颈排查

### 1. 慢SQL查询

```sql
-- 开启慢查询日志
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 0.1;

-- 查看慢查询日志
SELECT * FROM mysql.slow_log WHERE start_time > NOW() - INTERVAL 1 HOUR;

-- 使用EXPLAIN分析SQL执行计划
EXPLAIN SELECT * FROM appointment WHERE user_id = 1 AND schedule_id = 1;
```

**常见慢SQL**：
- 全表扫描
- 未使用索引
- 多表关联查询

**优化方案**：
- 添加联合索引
- 避免SELECT *
- 拆分复杂查询

### 2. Redis热点Key

```bash
# 查看Redis慢查询
redis-cli SLOWLOG GET 10

# 查看热点Key
redis-cli KEYS "hospital:stock:*"
redis-cli KEYS "rate:limit:*"
```

**优化方案**：
- 增加本地缓存（Caffeine）
- Redis集群部署
- 热点Key永不过期

### 3. 数据库连接池

```yaml
# 调整连接池配置
spring:
  datasource:
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000
```

### 4. 慢接口优化

**查看慢接口**：
```bash
# 查看日志中的慢请求
grep "慢请求告警" logs/hospital-appointment.log | tail -100
```

**优化策略**：
1. 添加索引
2. 增加缓存
3. 异步处理
4. 读写分离

## 📈 优化方案

### 优化1：添加联合索引

```sql
-- appointment表：用户+排班查询频繁
CREATE INDEX idx_user_schedule ON appointment(user_id, schedule_id, status);

-- schedule表：按日期查询频繁
CREATE INDEX idx_work_date_status ON schedule(work_date, status, available_count);

-- user表：手机号登录
CREATE INDEX idx_phone_status ON user(phone, status);
```

### 优化2：增加本地缓存

```java
// 使用Caffeine缓存热点数据
@Cacheable(value = "schedule", key = "#scheduleId", cacheManager = "caffeineCacheManager")
public ScheduleVO getScheduleDetail(Long scheduleId) { ... }
```

### 优化3：数据库读写分离

```yaml
spring:
  datasource:
    dynamic:
      primary: master
      datasource:
        master:
          url: jdbc:mysql://localhost:3306/hospital_appointment

          url: jdbc:mysql://localhost:3307/hospital_appointment
```

### SQL优化建议

```sql
-- ❌ 慢SQL：未使用索引
SELECT * FROM appointment WHERE user_id = 1;

-- ✅ 优化SQL：使用覆盖索引
SELECT appointment_id, schedule_id, status FROM appointment WHERE user_id = 1 AND deleted = 0;

-- ❌ 慢SQL：多表关联
SELECT a.*, h.hospital_name, d.department_name
FROM appointment a
LEFT JOIN hospital h ON a.hospital_id = h.hospital_id
LEFT JOIN department d ON a.department_id = d.department_id
WHERE a.user_id = 1;

-- ✅ 优化SQL：使用冗余字段
SELECT appointment_id, hospital_id, hospital_name, department_id, department_name
FROM appointment
WHERE user_id = 1 AND deleted = 0;
```

## 📞 压测问题排查

### 问题1：响应时间过长

**原因分析**：
1. 数据库慢查询
2. Redis网络延迟
3. MQ消息堆积

**排查步骤**：
```bash
# 1. 查看慢查询日志
mysql -u root -p -e "SELECT * FROM mysql.slow_log WHERE start_time > NOW() - INTERVAL 1 HOUR"

# 2. 查看Redis延迟
redis-cli --latency -h localhost -p 6379

# 3. 查看MQ队列长度
rabbitmqctl list_queues name messages
```

### 问题2：成功率低

**原因分析**：
1. 超卖导致数据库唯一索引冲突
2. 重复提交导致分布式锁冲突
3. Redis连接超时

**排查步骤**：
```bash
# 1. 查看错误日志
grep "ERROR" logs/hospital-appointment.log | tail -50

# 2. 查看数据库唯一索引冲突
mysql -u root -p -e "SHOW WARNINGS"

# 3. 查看Redis连接数
redis-cli INFO clients
```
